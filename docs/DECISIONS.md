# Decision log

Append a new entry in the same commit as any architectural change. Newest first.

- **2026-07-27 · NONET-8: Board and pad, and where UI work lives.** **React in `apps/web` but not Next.js yet.** Phase 2 needs somewhere to build components and Phase 3 owns the app shell, so `apps/web` gained React, vitest and a jsdom harness; components live in `apps/web/src/components` and Phase 3 adds routes around them. Nothing is wasted and the phase boundary holds. A Vite harness (`pnpm --filter @nonet/web dev`) renders a playable board for eyeballing before the shell exists — it is not product. **Components are controlled by the engine session.** `Board` and `NumberPad` render a `SessionState` and emit `Action`s; no rule is reimplemented in React. This is what keeps the two invisible rules honest — digit-first containment and undo-never-uncounting — and both are now covered end to end through the real UI path, not just in the reducer. **Accessibility is new work, not a port.** The prototype's tree comes back empty, so: `role="grid"` over rows and gridcells, a per-cell label carrying position, digit, given, notes and incorrect state, `aria-readonly` on givens, `aria-invalid` on bad entries, `aria-disabled` on a locked board, and a roving tabindex that follows selection without stealing focus from outside the grid. Full keyboard play per GAME-RULES; `P` is forwarded because the timer is not the board's to own. **Long-press belongs to the pad key, not the cell.** I had started building it on cells before rereading GAME-RULES — it is a pad gesture that pencils into the selected cell, and inventing a second gesture on cells would have been a rule nobody asked for. **A given is never flagged.** Found by looking at the running board: placing a duplicate painted both the entry and the innocent given red, leaving the player to work out which was theirs. Only the player's own entries can be wrong. **`loadedDigit` widened to `Digit | 'erase' | null`** so ERASE loads like a digit in digit-first, as the rules require. **Paint order matters for the box rules:** `box-shadow` paints the first shadow on top, so the 2px box rule has to precede the 1px hairline or the hairline covers it and the 3×3 structure stops reading. Rationale: the two bugs above were both invisible to unit tests and obvious the moment the thing was on screen, which is why the harness exists.

- **2026-07-27 · NONET-7: The last two token defects resolved.** Both were listed in `design/README.md` and both needed a decision rather than a transcription. **`--cell-hl` and `--hover` were the same value in dark** (`#22262A`). Checked before changing anything: `--hover` is outline-button and list-row hover, `--cell-hl` is board unit shading, and they never appear together — so the export's "indistinguishable" is a token-hygiene problem, not a visual one. It still matters, because two semantically separate tokens sharing a value move as one. Light draws them apart deliberately (ΔL\* 2.8 for unit shading, 3.2 for hover — hover reads a touch stronger because it is transient feedback rather than persistent ambient), and that relationship simply did not survive into dark. Dark `--hover` lifted to `#24292D`, sitting the same fraction further from the ground; `--cell-hl` untouched, because it is the board token and the board is not the thing at fault. **The dialog shadow did not re-tone.** One raw `rgba(0,0,0,.14)` served both themes: over the light scrim that darkens by ΔL\* 11.7, over the dark scrim (`--veil` `#15181B`, already L\* 8.1) it manages ΔL\* 1.5. Dark cannot match light at any alpha — pure black over that scrim tops out at ΔL\* 8.1 — so `SHADOWS` became themed and dark takes 0.55, giving ΔL\* 5.1, the most a shadow can usefully contribute before reading as a hard vignette. The real consequence is recorded next to the token: **in dark the dialog is separated by its `--rule` border, not by the shadow**, so the shadow is a supporting cue there and the border must not be dropped. Both are enforced by test — hover must sit further from the ground than unit shading, board shading must stay ordered (selection strongest), and the two shadows must differ in alpha while keeping identical geometry. Rationale: same as NONET-5 — measure where the token is actually used before changing it, preserve the design's own internal relationships rather than inventing new ones, and leave the reasoning where the next person will hit it.

- **2026-07-27 · NONET-6: Design tokens are code, and AA is a test.** `packages/design` transcribed from `design/export/tokens.json`: both palettes, 18 type roles, the 12-step space scale, motion, borders, shadow, radius, hatch, and CSS emission. Three decisions worth recording. **Contrast is computed, not transcribed.** The prototype shipped nine AA failures because contrast was measured once by hand into a JSON file; here `contrastRatio` is real code and `TEXT_PAIRINGS` records where each text colour is actually rendered, so the suite walks every pairing in both themes and fails the moment a colour moves. Pairings are deliberately not a cartesian product — combinations the product never renders would fail for no reason and train everyone to ignore the suite. `CONTRAST_EXEMPT` records `--fg3` and `--deco` with reasons, so "does not meet 4.5:1" reads as a decision rather than an oversight. **Type steps at the layout breakpoints, not the drawing widths.** The export specifies values at 390/834/1440 and NONET-2 puts the switches at 768/1100; joining them is an inference and is marked as one on `viewportForWidth`. **Defects are not transcribed as tokens.** The export's 26 off-scale spacing values and the off-role type renderings are recorded there as defects, so the package exports only the published scale and carries the drift in per-role notes; `nearestSpace` exists to snap a ported measurement. Two token-level defects are left as measured because resolving them is a design decision nobody has made: the dialog shadow does not re-tone in dark, and `--cell-hl` and `--hover` are the same value in dark, making unit shading and row hover indistinguishable. Both are listed in the package README. Rationale: the whole reason `--fg3` reached export with nine failures is that the token sheet was a document. A document cannot fail; a test can.

- **2026-07-27 · NONET-5: `--fg3` split in two; the AA failure is resolved.** `design/README.md` recorded this as "`--fg3` on `--bg` = 4.34:1 in light", which framed it as one near-miss. It is nine failures across both themes, and the `--bg` case is the mildest: light `--fg3` also fails on `--veil` 4.19, `--hover` 4.00, `--cell-hl` 4.03, `--cell-same` 3.98 and `--cell-sel` **3.61**, and dark fails on `--cell-same` 4.48 and `--cell-sel` 3.72. **Root cause: one token doing four jobs** — note text inside cells, inactive interactive states, disabled/spent states, and captions/kickers/metadata — each with different backgrounds and different requirements, which is why no single value could satisfy them. Resolved by splitting rather than compromising. **`--fg3` stays exactly as designed** (light `#6C7278`, dark `#8B9298`) and is **scoped to disabled and spent states only**, which WCAG 1.4.3 exempts; spent pad keys already carry a non-colour cue (GAME-RULES.md), so nothing rests on contrast there. **New `--fg3-text` (light `#5A5F65`, dark `#A0A6AA`)** carries every caption, mono kicker, metadata string, inactive interactive state **and note text**. Worst pairing is note text on `--cell-sel` at 4.79:1 light / 4.77:1 dark, against a 4.5:1 floor — the value was chosen for ~0.27 of headroom rather than the exact 4.50 minimum, so a later token tweak or a browser rounding difference cannot silently reintroduce the failure. **Cost, accepted:** the light `--fg2`→third-tier gap narrows from 13.6 to 6.0 L\*, so the third tier recedes less. Rejected the alternative of re-spacing `--fg2` darker (to `#373B40`, restoring even 16.5/17.1 gaps) because `--fg2` already passes comfortably at 7.17:1 and moving it would push body copy toward near-black across the whole product — a far larger change to the design language than the defect warrants. The collapse is survivable because `--fg2` and the third tier are adjacent in only two components (dialog kicker over body, banner dismiss over body) and in both the separation is carried by family, size, case and tracking — 11px tracked uppercase mono against 15px sentence Archivo — with tone as reinforcement, not the primary signal. Also rejected: darkening `--fg3` to clear `--bg` alone (`#6A6F75`), which fixes the one number the README quotes and leaves the other eight failing; and lightening the shaded cell backgrounds (`--cell-sel` `#D7DDF9`→`#F4F6FD`), which bleaches the cobalt out of cell selection, the board's most important affordance. Rationale: AA is a stated hard requirement and the note-on-selected-cell case is where players actually read small text, so the token that carries it has to be sized to its worst background, not its most common one. **Still open and unrelated:** the six sub-44px touch targets in `export/layout.md` are a separate AA failure that also blocks launch.

- **2026-07-27 · NONET-4: Difficulty is a weighted effort score (supersedes the rater in NONET-3).** NONET-3 rated by given count with the technique ceiling as an upward guard. That was measured and honest but it made the band labels weak: a ceiling is a maximum over the solve, so it discards *how much* hard work a puzzle takes, and the given-count axis meant "Expert" often just described a sparse grid that fell to singles. Replaced with a single number: **score = the summed weight of every step the human solver takes**, in naked singles (nakedSingle 1, hiddenSingle 2, nakedPair 5, hiddenPair 8, nakedTriple 10, pointingPair 12, boxLine 14, xWing 30, chain 50). Steps, not eliminations — one naked-pair step is one deduction a human made, not six. Because the solver is greedy cheapest-first the score measures the easiest available path, which is what a competent solver would find, and it stays deterministic. **Given count is no longer consulted**: it is already implicit, since a puzzle needs `81 - givens` placements and each costs at least a point, so a singles-only grid scores exactly `81 - givens`. That "scanning baseline" is what the bands are set against. **Bands** (calibrated over 500 digs per band): Easy < 47, Medium 47-57, Hard 58-82, Expert ≥ 83, against baselines of 43/47/51/57 — so Hard demands 7 points of technique beyond scanning and Expert 26. That margin is the whole point of the change. **The ceiling guard is gone** — the weights already price technique (one chain step is 50, enough to carry almost anything to Expert), and two axes meant two sources of truth. `TECHNIQUE_CEILINGS` survives only as the generator's dig bound. **The generator re-rolls** until the score lands in band, keeping the design given counts exact (38/34/30/24) at the cost of attempts: measured in-band rates per dig are Easy 97%, Medium 95%, Hard 42%, Expert 26%, so Expert needs about four digs; `MAX_ATTEMPTS` 40 puts failure near 4 in 100,000, and generation runs once a day. **Thresholds are calibrated, weights are judgement.** `scripts/calibrate.ts` is checked in and re-derives the floors, placing each at the percentile of its band's own distribution that leaves a target share qualifying (95% Easy/Medium, 40% Hard, 25% Expert) — deliberately *not* the best-separating threshold, because the four dig populations are separated mainly by their baselines and optimal separation just recovers given-count banding. The weights cannot be calibrated without human solve times, so the plan is to persist `score` on the `puzzles` row in Phase 3, then re-derive weights from real completion times and re-band the bank with a script. Consequence worth noting: the canonical Wikipedia grid (30 givens, singles-only) now rates Medium at 51 points, where the NONET-3 rater called it Hard. Rationale: the product promises four distinct difficulties, and a band that a player cannot feel the difference of is a label, not a difficulty.

- **2026-07-27 · NONET-3: Engine architecture (Phase 1).** `packages/engine` built test-first: pure TS, no runtime dependencies, vitest only. **Technique ladder** — nine techniques applied strictly cheapest-first: naked single, hidden single, naked pair, hidden pair, naked triple, pointing pair, box-line reduction, X-wing, chain (simple colouring). Naked triple is an addition to the order named in ROADMAP; it is cheap and stops Medium puzzles falling through to fish techniques. The order is load-bearing: because the solver always reaches for the cheapest applicable technique, the hardest technique a puzzle forces is a stable property of that puzzle, and the rater, the generator's dig bound and the hint ranking all read it. Reordering `TECHNIQUE_ORDER` re-rates the whole bank. Cell iteration is fixed and no technique uses randomness, so `analyse` is deterministic. **Difficulty rating — given count is the primary axis, technique ceiling can only raise the band.** This reverses the plan I opened with, and the reversal is data-driven: digging to the design given counts leaves a singles-only grid most of the time, even at 24 givens (24 of 30 sampled Expert-count grids had a ceiling of 2, and ranks 6-7 almost never appear as the hardest technique needed). Hardest-technique and given count are close to independent in this range, so requiring both to land in a window simultaneously made Expert generation fail outright for roughly 3% of seeds. A ceiling cannot define a band from below; it can only bound one from above. Bands: Easy 37+ givens / ceiling ≤ 2, Medium 33-36 / ≤ 5, Hard 27-32 / ≤ 7, Expert ≤ 26 / ≤ 9. A grid deduction cannot finish rates Expert. **Generator guarantees uniqueness by construction** — digging starts from a complete solution and clears a cell only if the grid still has exactly one solution afterwards, so a second solution can never appear; re-checked before the puzzle is returned. "Never requires a guess" holds the same way: a removal is only accepted if the human solver can still finish within the band's ceiling. Digging stops on reaching the target count, so puzzles are never sparser than the design asks, only occasionally denser when no further cell can be cleared. **No 180-degree symmetry** — symmetric digging removes cells in pairs and can only leave an odd given count, and all four design targets are even; the design rules symmetry out. **Undo/redo and mistakes live in the engine** as a pure session reducer, because "undo never uncounts a mistake and never restores a spent hint" is only testable where history, tally and hints sit together, and it keeps those rules out of React. History carries the grid and notes only; hints are burned into every stored snapshot so undo cannot lift one. Rationale: the engine is the one place these rules can be proven, and the two that are invisible in any screenshot — digit-first mistake containment and undo-versus-tally — are exactly the ones a UI would otherwise get wrong.

- **2026-07-27 · NONET-2: Full-surface design resolved (pre-code).** Eight review passes against the Claude Design full-surface build, grilled screen by screen. **Navigation:** Practice folded into Home — it was a nav destination duplicating an identical Home section, so nav is now Today · Archive · Record and there is no `/practice` route; the practice picker, resume band and abandon confirm all live on Home. **Board input:** two modes, cell-first (default) and digit-first, chosen in Settings and switchable on the board; long-press a pad key writes a note (four taps → two); `Shift`+digit is the keyboard equivalent; pad keys become non-interactive at zero remaining; auto-advance is a setting, off by default. **Digit-first mistake containment:** while a digit stays loaded, repeated wrong placements of that same digit count as one mistake — without this, three fast taps end a puzzle, a cliff that only exists because the mode is fast. This is an engine rule and needs a unit test. **Hint guard:** the first hint per puzzle confirms once (it is irreversible and forfeits the percentile); hints two and three go straight through. **Exiting a puzzle:** immersive board retained, but `CLOSE` replaced by a left-aligned back control labelled for its origin (`← TODAY` / `← ARCHIVE`) — "close" implied discard on an autosaved puzzle. **Archive vs Record:** they were one component serving two jobs; now Record is a non-interactive year heat strip (a month cannot show a 61-day run) and Archive is a navigable month grid carrying difficulty per cell plus a filter rail. **Guest→signed-in merge:** the rule already existed but had no surface; a post-sign-in summary now reports what merged, which run stands and which in-progress puzzle was kept — it reports, it never asks. **Responsive:** mobile drawer below 768px, single-row site header above it, board rail at 1100px+ and bottom control band below. **Tokens:** colour, type, space and motion all named on a dedicated Tokens screen in the prototype, which is the transcription source for `packages/design`. **Accessibility:** focus states designed visually (distinct from cell selection) in the prototype; real ARIA/semantics are the build's job, as the design runtime cannot express them. Rationale: the prototype is a pixel and behaviour reference for a from-scratch build, so quirks resolved here are quirks not baked into code.

- **2026-07-26 · NONET-1: Founding product + design decisions (pre-code).** Grilled and locked before any code exists. Product: daily (shared grid, 00:05 UTC, weekly difficulty rhythm) + unlimited practice from a pre-built bank; free, no paywall/ads UI in v1; archive free and playable but never extends streaks (streak honesty > engagement). Fail model: 3/3 mistakes locks the board, retry from scratch allowed, pre-midnight solve keeps streak marked "second attempt" with no percentile — stakes without Wordle-severity. Auto-check on by default with a purist off-toggle (off = unchecked solve, no tally). Hints: 3 reveals/puzzle, marks solve assisted, no percentile. Accounts mirror Halve: guest-first localStorage, optional magic-link sign-in for sync, streaks derived from `solves` by local calendar day. Pause veils the grid; auto-pause on blur. Share = spoiler-free text + link. v2 (nothing designed): leaderboards/social, auto-candidate notes, image share card, PWA/offline, streak freeze, sound. Design locked from Claude Design prototype: cool/architectural Swiss, bone/graphite + cobalt, grotesque + mono, "NONET" wordmark, givens-bold/yours-cobalt/notes-small; Halve's warm-editorial ingredients explicitly forbidden. Rationale: reuse Halve's proven architecture wholesale (engine package, derived streaks, guest-first auth, daily edge function) so novelty budget is spent on the sudoku engine and the new design language, not re-litigated infrastructure.
